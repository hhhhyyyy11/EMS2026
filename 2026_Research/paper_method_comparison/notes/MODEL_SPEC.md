# 共通モデル仕様と過去実装の対応

作業ID：T01  
確定日：2026-09-13  
正本：`README.md` 第4〜7節・第11節  
参照実装：`../src/optimize_LP.py`、`../src/optimize_DP.py`、`../config.json`

## 1. この文書の役割

需要、PV、蓄電池1台、系統買電からなるEMSについて、数理計画法と動的計画法（DP）が同じ問題を解くための共通仕様を固定する。過去実装は比較対象ではなく参照資料であり、以下の共通モデルと異なる挙動は新規実装へ持ち込まない。

共通モデルは、既知の需要・PV・買電単価に対し、対象期間の最大買電電力を契約電力相当値として評価する基本料金と、買電量に応じた電力量料金の合計（以下「電力料金」）を最小化する。売電、外生的な買電上限、自己放電、電池劣化は扱わない。

## 2. 時刻と添字

- 最適化対象を `N` 個の時間区間に分け、区間を `t = 0, ..., N-1` とする。
- 区間 `t` は境界時刻 `t` から `t+1` までであり、幅を `dt` [h] とする。
- 需要、PV、価格、買電、充放電電力は各区間に1値を持つため、すべて `N` 点である。
- 蓄電量 `e[t]` は区間境界の状態であり、初期境界 `e[0]` から終端境界 `e[N]` まで `N+1` 点である。
- 区間 `t` の充放電によって `e[t]` から `e[t+1]` へ遷移する。30分値では `dt = 0.5` hである。

## 3. 入力とパラメータ

| 論文用記号 | 意味 | 単位 | 点数・範囲 | 初期値 |
|---|---|---:|---|---:|
| `N` | 時間区間数 | — | 正の整数 | 対象期間から決定 |
| `dt` | 1区間の時間幅 | h | `dt > 0` | 0.5 |
| `load[t]` | 区間平均の需要電力 | kW | `t=0,...,N-1`、0以上 | 入力データ |
| `pv_available[t]` | 利用可能な区間平均PV電力 | kW | `t=0,...,N-1`、0以上 | 入力データ |
| `price[t]` | 買電単価 | 円/kWh | `t=0,...,N-1` | 入力データ |
| `p_basic_month` | 月額基本料金単価 | 円/kW/月 | 正 | 2,829.60 |
| `f_power` | 力率補正係数 | — | 正 | 0.85 |
| `C_basic_year` | 力率補正後の年間基本料金単価 | 円/kW | `p_basic_month f_power * 12` | 28,861.92 |
| `w_basic` | 対象期間へ按分した基本料金係数 | 円/kW | `C_basic_year * (N dt) / 8760` | 期間から決定 |
| `E_max` | 電池の定格容量 | kWh | 正 | 860 |

| `E_min`, `E_max_op` | 運用蓄電量の下限・上限 | kWh | `r_min E_max`、`r_max E_max` | 43、817 |
| `C_max` | 電池内部側の最大充電電力 | kW | 0以上 | 400 |
| `D_max` | 電池内部側の最大放電電力 | kW | 0以上 | 400 |
| `eta_c` | 外部から内部への充電効率 | — | `0 < eta_c <= 1` | 0.98 |
| `eta_d` | 内部から外部への放電効率 | — | `0 < eta_d <= 1` | 0.98 |

`E_max` は定格容量、`E_max_op` は運用上限であり、混同しない。設定名 `charge_limit_kW` と `discharge_limit_kW` は、共通モデルでは電池内部側の上限として解釈する。

## 4. 決定変数

| 論文用記号 | 意味 | 単位 | 位置 | 時刻 |
|---|---|---:|---|---|
| `buy[t]` | 系統からの買電電力 | kW | 系統側 | 区間 `t` |
| `pv_used[t]` | 実際に利用するPV電力 | kW | 交流母線側 | 区間 `t` |
| `c[t]` | 電池へ蓄えられる充電電力 | kW | 電池内部側 | 区間 `t` |
| `d[t]` | 電池から取り出す放電電力 | kW | 電池内部側 | 区間 `t` |
| `e[t]` | 電池の蓄電量 | kWh | 電池内部状態 | 境界 `t` |
| `z[t]` | 充電・放電モード | — | `1`で充電許可、`0`で放電許可 | 区間 `t` |
| `p_contract` | 対象期間の最大買電電力（契約電力相当値） | kW | 系統側 | 期間全体 |

外部側の充電電力は `c[t] / eta_c` [kW]、外部側へ供給される放電電力は `eta_d d[t]` [kW] である。本研究では百分率としてのSOCと区別するため、最適化状態 `e[t]` の実体を蓄電量 [kWh] とする。必要な場合だけ `soc_ratio[t] = e[t] / E_max` と換算する。

## 5. 共通の最適化問題

### 5.1 目的関数

対象期間の基本料金相当額と電力量料金の合計である電力料金を最小化する。

```text
C_basic_year = p_basic_month * f_power * 12
w_basic = C_basic_year * (N * dt) / 8760

minimize  J = w_basic * p_contract
              + sum(t=0,...,N-1) price[t] * buy[t] * dt
```

第1項は基本料金相当額、第2項は電力量料金である。第1項は `(円/kW) * (kW) = 円`、第2項は `(円/kWh) * (kW) * (h) = 円` であり、`J` の単位は円で一致する。年間基本料金単価は対象時間 `N*dt` の年間8760時間に対する比で按分し、期間長の異なる実験で同じ規則を使う。

### 5.2 最大買電電力と契約電力相当値

```text
p_contract >= buy[t]       (t=0,...,N-1)
p_contract >= 0
```

`w_basic > 0` なので、最適解では `p_contract = max_t buy[t]` となる。これは基本料金を評価するための上包絡変数であり、外部から与える買電上限やデマンド目標値ではない。実際の過去12か月を参照する月別契約電力ではなく、過去LPと同じく対象期間内の最大買電を契約電力の代理値とする近似である。

### 5.3 電力収支とPV抑制

各区間について、交流母線側の電力収支を満たす。

```text
buy[t] + pv_used[t] + eta_d * d[t]
    = load[t] + c[t] / eta_c
```

```text
buy[t] >= 0
0 <= pv_used[t] <= pv_available[t]
```

`pv_available[t] - pv_used[t]` がPV抑制量である。売電変数は置かないため逆潮流は生じない。また、この等式と非負制約により、需要や充電先のない電力を暗黙に廃棄することを認めない。

### 5.4 SOC遷移と範囲

```text
e[t+1] = e[t] + dt * (c[t] - d[t])
E_min <= e[t] <= E_max_op              (t=0,...,N)
```

右辺の変化量は `(kW) * (h) = kWh` であり、両辺の単位はkWhで一致する。効率は電池外部との受渡しに適用済みなので、SOC遷移式の `c[t]` と `d[t]` へ重ねて掛けない。

### 5.5 充放電電力と排他

基準MILPでは、実際の内部電力上限をそのまま使って同時充放電を禁止する。

```text
0 <= c[t] <= C_max * z[t]
0 <= d[t] <= D_max * (1 - z[t])
z[t] in {0, 1}
```

待機時は `c[t] = d[t] = 0` であり、`z[t]` はどちらでもよい。`1e6` のようなモデル規模と無関係なBig-Mは使わない。

### 5.6 初期・終端条件

```text
e[0] = E_initial = 0.5 * E_max
e[N] = E_terminal = 0.5 * E_max
```

初期と終端を同じにすることで、対象期間の外から持ち込んだ電池エネルギーを使って費用を過小評価することを防ぐ。

## 6. 手法ごとの表現

### 6.1 基準MILP

第5節の問題を連続変数 `buy`、`pv_used`、`c`、`d`、`e`、`p_contract` と二値変数 `z` でそのまま解く。連続SOCを用いる基準候補であり、終了状態、最良境界、最適性ギャップを保存する。

### 6.2 診断用LP

単純な上下限 `0 <= c[t] <= C_max`、`0 <= d[t] <= D_max` は保ち、二値変数 `z[t]` と排他を表す2本の制約だけを外す。それ以外の目的関数、電力収支、効率、SOC、初期・終端条件は基準MILPと同一にする。

LPはMILPとの目的値、運用、同時充放電の有無を調べる診断用である。目的値が一致しただけで物理的に同じ運用とは判断せず、論文で数理計画法の代表にできるかはE0以降の結果で決める。

### 6.3 DP

`e[0],...,e[N]` をSOC格子上の状態とし、区間 `t` の遷移差 `delta_e = e[t+1] - e[t]` から内部電力を求める。

```text
delta_e >= 0: c[t] = delta_e / dt, d[t] = 0
delta_e <  0: c[t] = 0, d[t] = -delta_e / dt
```

したがって、1回の遷移内で充電と放電は同時に生じない。各遷移について第5節の電力上限、電力収支、PV利用範囲を検査する。初期・終端の50%を丸めず正確に含む、5〜95%の等間隔な入れ子格子を用いる。初期候補の19、37、73、145点はいずれも中央に50%を含む。

基本料金は経路上の最大買電に依存するため、SOCごとに「現在までの最大買電 `peak_so_far` [kW]」と「累積電力量料金 [円]」の非劣解ラベルを保持する。遷移では `peak_next = max(peak_so_far, buy[t])` と更新し、同一SOCで最大買電と累積電力量料金の両方が他ラベル以下のラベルだけを残す。終端SOCが50%のラベルについて `w_basic * peak_so_far + energy_charge` を評価する。このラベル方式により、最大買電用の恣意的な格子を追加せず、SOC格子だけを離散化要因としてMILPと同じ離散問題を解く。

## 7. 共通変数と過去実装の対応

| 共通概念 | 論文用記号 | 過去LP | 過去DP | 対応上の注意 |
|---|---|---|---|---|
| 利用可能PV | `pv_available[t]` | `gP1[k]` | `gP1[data_idx]` | 過去実装は負値を0へ補正 |
| PV利用 | `pv_used[t]` | `gP2[k]` | 明示変数なし | DPは利用可能PVを全量控除後に系統電力を0で切る |
| 需要 | `load[t]` | `dA2[k]`。`dB2`,`dC2`は0 | `dA2[data_idx]` | 過去LPの需要変数 `dA1`〜`dC1` は入力値に固定 |
| 買電 | `buy[t]` | `sBY[k]` | `p_buy` | 共通モデルに上限はない |
| 最大買電・契約電力相当値 | `p_contract` | `sBYMAX_var` | `max_buy_power_observed`（事後集計のみ） | 基本料金の評価に使用 |
| 外部充電 | `c[t]/eta_c` | `xFC1[k]` | `p_fc1` | kW |
| 内部充電 | `c[t]` | `xFC2[k]` | `p_fc2` | 上限を適用する側 |
| 内部放電 | `d[t]` | `xFD1[k]` | `p_fd1` | 上限を適用する側 |
| 外部放電 | `eta_d d[t]` | `xFD2[k]` | `p_fd2` | kW |
| 蓄電量 | `e[t]` | `bF[k]` | `soc_levels[i/j]` | 過去LPの `bF[k]` は共通モデルの `e[k+1]` に相当 |
| 排他 | `z[t]` | `z[k]` | SOC差の符号で暗黙に選択 | 過去LPは過大なBig-Mを使用 |
| 買電単価 | `price[t]` | `pBY[k]` | `pBY[data_idx]` | 円/kWh |
| 月額基本料金単価 | `p_basic_month` | 式中の定数 `2829.60` | なし | 円/kW/月 |
| 力率補正 | `f_power` | 式中の定数 `0.85` | なし | 無次元 |
| 按分基本料金係数 | `w_basic` | `pBYMAX_weight` | なし | 円/kW |
| 時間幅 | `dt` | 定数 `0.5` | 定数 `0.5` | h |

## 8. 過去LP実装との差

確認対象は `../src/optimize_LP.py` である。

| 項目 | 過去LP | 共通モデルでの扱い |
|---|---|---|
| 目的関数 | 最大買電の最小化、または按分した基本料金と電力量料金の合計をモード選択 | 基本料金と電力量料金の合計に固定 |
| 最大買電 | `sBYMAX_var` を各時刻の買電以上とし、目的関数へ含める | 同じ上包絡を `p_contract` として採用 |
| 基本料金係数 | `2,829.60 * 0.85 * 12 * (K*0.5)/(24*365)` | 同じ期間按分式をパラメータ名と単位を明示して採用 |
| 買電上限 | `sBYMAX=1000` を定義するが制約には未使用 | 上限を置かない |
| 売電 | `sSL[k]` が存在し、0円に微小ペナルティを加えて抑制 | 売電変数を置かない |
| PV抑制 | `gP2<=gP1` に加えて余剰吸収変数 `v[k]` が存在 | `0<=pv_used<=pv_available` のみで明示 |
| SOC時刻 | `bF[k]` は区間 `k` 適用後の状態で、K点 | `e[0]`〜`e[N]` のN+1境界点 |
| 初期条件 | `bF[0]=bF0+dt*(xFC2[0]-xFD1[0])` と埋込み | `e[0]=E_initial` を独立に固定 |
| 終端条件 | なし | `e[N]=E_terminal` を固定 |
| 排他 | 外部充電 `xFC1` と内部放電 `xFD1` に `M=1e6` を使用 | 内部電力の実上限 `C_max`,`D_max` を使用 |

過去ファイル名は `optimize_LP.py` だが、二値変数を含む通常モードはMILPである。

## 9. 過去DP実装との差

確認対象は `../src/optimize_DP.py` である。

| 項目 | 過去DP | 共通モデルでの扱い |
|---|---|---|
| 目的関数 | 電力量料金だけを累積 | 最大買電の非劣ラベルも保持し、終端で基本料金を加算 |
| 買電上限 | `p_buy_max=170.0` kWを遷移の実行可能条件に使用 | 買電上限を置かない |
| 初期SOC | 格子上で50%に最も近い点を選ぶ | 50%を正確に含まない格子を不許可にする |
| 終端SOC | 最終時刻の全状態から最小費用を選ぶ | 50%の終端状態だけを許可 |
| PV抑制 | 利用可能PVを全量差し引き、負の系統電力を0へ切り上げる | `pv_used` を明示し、電力収支を等式で検査 |
| 余剰放電 | 負の残差を0にするため、PV余剰ではない過大放電も暗黙に消失し得る | `pv_used>=0` と電力収支により不可能 |
| 格子 | 容量比の幅から点数を丸めて生成。10%指定時の格子は50%を含まない | 19/37/73/145点の入れ子格子で50%を厳密に含む |
| 出力 | 費用・時間・最大買電の要約のみ | 共通形式の全時系列と事後制約検査を後続タスクで実装 |

## 10. 対象外と禁止事項

共通モデルへ次を導入しない。

- 外生的な買電電力のハード上限、契約需要上限、デマンド目標値制約
- 最大買電だけを最小化する目的
- 過去12か月の実績を使う月別契約電力更新（最初の手法比較では対象期間最大値を代理値とする）
- 売電または逆潮流
- 複数地点、潮流、電圧制約
- 自己放電、電池劣化、予測誤差、リアルタイム制御
- 複数蓄電池

これらが必要になった場合は、比較実験へ黙って追加せず研究計画の変更として相談する。
