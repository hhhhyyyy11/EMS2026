## 3. 需要・PVデータ

入力: `../Data/common_energy_data.xlsx`、シート `30分値`

| 列 | 解釈 | 元単位 | 共通モデルへの変換 |
|---|---|---|---|
| `日付` | 区間の日付 | 日時 | 日付部分を使用 |
| `時刻` | 区間開始時刻 | 時刻 | 日付へ加算後、許容範囲内で30分格子へ丸める |
| `消費電力量` | 30分の需要電力量 | kWh/30分 | `load_kW = 2 * 消費電力量` |
| `発電量` | 30分のPV発電電力量 | kWh/30分 | `pv_kW = 2 * 発電量` |
| `Unnamed: 0` | 空列 | なし | 使用しない |

先頭の単位行を含む生データは17,521行である。`消費電力量` が数値でない単位行1行だけを除くと次のとおり。

| 点検項目 | 結果 |
|---|---|
| 期間 | 2025-01-01 00:00〜2025-12-31 23:30 |
| 有効件数 | 17,520（365日×48点） |
| 日ごとの件数 | 全365日で48点 |
| 欠測 | 需要0、PV 0、日時0 |
| 重複時刻 | 0 |
| 負値 | 需要0、PV 0 |
| 需要範囲 | 6〜132 kWh/30分、変換後12〜264 kW |
| PV範囲 | 0〜97 kWh/30分、変換後0〜194 kW |

Excelの浮動小数点表現により、17,520点中15,133点の時刻に1〜4 msのずれがある。30分格子からの最大偏差は4 msで、5 ms以内の値を最近接30分へ丸めると、重複なし・連続17,520点になる。5 msを超える偏差は入力エラーとする。

## 4. 価格データ

CSVはShift_JISで読み込める。主実験で使う列は `受渡日`、`時刻コード`、`エリアプライス北海道(円/kWh)` である。

| ファイル | 収録期間 | 件数 | 日別件数 | 北海道価格 | 価格範囲 |
|---|---:|---:|---:|---|---:|
| `spot_summary_2023.csv` | 2023-04-01〜2024-03-31 | 17,568 | 366日すべて48点 | あり | 0.01〜50.00円/kWh |
| `spot_summary_2024.csv` | 2024-04-01〜2025-03-31 | 17,520 | 365日すべて48点 | あり | 0.01〜49.65円/kWh |
| `spot_summary_2025.csv` | 2025-07-03〜2025-07-16 | 672 | 14日すべて48点 | **なし（四国のみ）** | 四国0.01〜35.00円/kWh |

3ファイルとも受渡日・時刻コードの組に重複はなく、各収録日はコード1〜48を各1回持つ。北海道列のある2ファイルに価格欠測はない。`spot_summary_2025.csv` は期間が部分的で地域も異なるため、本研究の北海道系列には使用しない。

JEPXは一日前市場を1日48個の30分商品としており、最初の区間は00:00〜00:30、次は00:30〜01:00、最後は23:30〜24:00である（[JEPX取引ガイド](https://www.jepx.jp/electricpower/outline/pdf/Guide_2.00.pdf)）。元CSVも各日でコード1〜48を一度ずつ持つため、開始時刻を次式で作る。

```text
datetime = 受渡日 + (時刻コード - 1) * 30分
コード1 = 00:00、コード2 = 00:30、コード48 = 23:30
```

価格列の単位は円/kWhである。Excelの `備考` と既存市場連動処理に合わせ、共通モデルへ渡す価格は次の値とする。

```text
price[t] = 北海道エリアプライス[t] + 3.98 円/kWh
```

## 5. 共通期間とE1入力

固定価格を使う主実験では価格CSVとの結合が不要である。需要・PVの完全な2025年通年を共通期間とし、E1は当初候補だった7月22日を採用する。

| 点検項目 | 共通365日 | E1 1日 | E1 7日 |
|---|---:|---:|---:|
| 期間 | 2025-01-01〜2025-12-31 | 2025-07-22 | 2025-07-22〜2025-07-28 |
| 期待件数 | 17,520 | 48 | 336 |
| 実測件数 | 17,520 | 48 | 336 |
| 欠測 | 0 | 0 | 0 |
| 重複 | 0 | 0 | 0 |
| 価格 | 21.51円/kWh（全時刻） | 21.51円/kWh（全48点） | 21.51円/kWh（全336点） |

範囲の終端は半開区間で扱う。1日は `[2025-07-22 00:00, 2025-07-23 00:00)`、7日は `[2025-07-22 00:00, 2025-07-29 00:00)` とする。

## 6. 確定した前処理と停止条件

1. エネルギー表の必須4列を確認し、単位行だけを数値検査により除く。需要・PVは数値かつ非負を必須とする。
2. `日付` の日付部分と `時刻` を別々に解析して合成する。30分格子との偏差が5 ms以内だけ最近接格子へ丸め、それ以外は停止する。
3. 需要・PVをkWh/30分から平均kWへ2倍して変換する。
4. 価格は設定で指定した21.51円/kWhを対象区間の全時刻へ生成し、値・単位・適用点数を保存する。
5. 対象半開区間について、需要・PVが同じ48点/日を持つことを確認する。
6. 需要・PVの欠測、重複、非30分間隔、件数不一致を検出したら停止する。

## 7. 既存処理との差と使用可否

`../Shared/data_loader.py` の市場価格処理には次の問題がある。ただし主実験は固定価格なので、同処理を通さない。

- `read_jepx_prices` はコード1行を `[0分, 30分]` の2点へ展開し、コードを時間として扱う。48コード/日は既に30分値なので、正しくは1コードから1点である。
- コード2を01:00へ置くなど、コード2=00:30という対応からずれる。さらにコード25〜47は翌日にあふれ、重複削除によって別コードの価格が残る。
- エネルギー側の最大4 msのずれを補正せず厳密結合する。共通90日4,320点のうち既存時刻と厳密一致するのは一部だけになる。
- 市場価格欠測を固定単価21.51円/kWhで埋めた後に賦課金を加えるため、不整合を成功扱いしてしまう。
- 現在の `config.json` は `fixed_price` であり、今回の主実験設定と一致する。

したがって既存環境と基礎ライブラリは使用可能である。T03以降では論文フォルダ内に、需要・PVの検査と固定価格生成だけを行う前処理を新規実装する。

## 9. 検証コマンドの要約

仮想環境のPythonからpandas/openpyxlでExcelとCSVを読み、数値化、日時正規化、30分格子、日別件数、欠測、重複、負値、価格範囲、内部結合件数を集計した。PySCIPOptでは1変数の最小化問題を実際に解いた。ファイル識別には `shasum -a 256`、空き容量には `/bin/df -h .` を用いた。
