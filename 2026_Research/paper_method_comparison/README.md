# EMSにおける数理計画法・動的計画法の比較研究計画

最終更新: 2026-09-16  
状態: 研究目的・実験・作業を中心にした統合版。

> 別セッションから作業を再開する場合は、最初に [START_HERE.md](START_HERE.md) を確認する。

## 1. 研究の目的

需要、太陽光発電（PV）、蓄電池を持つ系統連系EMSについて、数理計画法と動的計画法（DP）を同じ条件で比較する。

比較を通して明らかにしたいのは、問題の期間やDPのSOC離散化を変えたときに、解の費用、計算時間、メモリ使用量がどのように変化するかである。最終的には、求める精度と利用できる計算資源に応じて、手法を選ぶ際の具体的な判断材料を示す。

仮題: **蓄電池を用いたエネルギーマネジメントにおける数理計画法と動的計画法の比較：解品質と計算負荷の評価**

本研究は、まず自分たちのEMSモデルと実データを基礎に進める。先行研究は研究の方向を決める起点にはせず、定式化の確認、結果の解釈、論文上の位置づけに利用する。

## 2. 対象範囲

本研究の対象は、需要、PV、蓄電池1台、系統からの買電で構成される需給運用である。

| 項目 | 範囲 |
|---|---|
| 運用 | 蓄電池の充放電と系統からの買電 |
| 目的 | 最大買電に基づく基本料金と電力量料金の合計（電力料金）を最小化 |
| 情報 | 対象期間の需要、PV、価格を既知として両手法に同じ値を与える |
| 時間 | 30分値から開始し、実験では期間と時間刻みを変更 |
| 電力網 | 単一地点の電力収支を扱う |
| 対象外 | 電圧、潮流、複数地点間のネットワーク制約 |

主実験は決定論的なオフライン最適化とする。予測誤差、リアルタイム制御、複数蓄電池、電池劣化は、基本比較が完成した後に必要性を判断する。

## 3. 研究課題

- **RQ1：解品質** — DPのSOC格子を細かくしたとき、数理計画法の解に対する費用差はどのように変化するか。
- **RQ2：計算負荷** — 計画期間、時間刻み、SOC格子数を変えたとき、両手法の計算時間とメモリ使用量はどのように変化するか。
- **RQ3：条件による違い** — 季節、蓄電池の容量と出力の比を変えたとき、RQ1・RQ2の関係はどのように変化するか。
- **RQ4：選択の目安** — 指定した費用誤差と計算資源の範囲に対し、各手法を選ぶ目安を示せるか。

暫定的には、DPはSOC格子を細かくするほど費用差が小さくなり、計算量が増えると予想する。ただし、比較結果はモデル、実装、入力条件に依存するため、実験結果から判断する。

主張は、蓄電池1台とSOCを物理状態とする本研究の範囲に限定する。DPでは基本料金を正しく評価するため、SOCごとに累積最大買電と電力量料金の非劣ラベルも保持する。高次元の問題への一般的な優劣は、この実験だけから結論づけない。

## 4. 共通モデル

両手法が同じ問題を解くよう、以下の仕様を共通化する。

| 項目 | 初期仕様 |
|---|---|
| システム | 需要、PV、蓄電池1台、系統買電 |
| 時間刻み | 30分 |
| 目的関数 | 対象期間最大買電に基づく基本料金相当額＋各時刻の電力量料金 |
| 買電 | 0以上 |
| 契約電力相当値 | 対象期間内の最大買電電力。外生的な上限にはしない |
| 基本料金 | 2,829.60円/kW・月×力率補正0.85×12を対象時間で按分 |
| PV | 発電量以下で利用し、余剰分は抑制可能 |
| 売電 | 扱わない |
| SOC | 容量の5〜95% |
| 初期・終端SOC | 50% |
| 蓄電池容量 | 860 kWhから開始 |
| 最大充放電電力 | 電池内部側で400 kWから開始 |
| 充放電効率 | 充電0.98、放電0.98 |
| 同時充放電 | 禁止 |
| 自己放電 | 扱わない |
| 価格 | 固定価格21.51円/kWhを全期間・全手法で使用 |

価格は `../config.json` の既存値21.51円/kWhで固定する。時間帯別価格による裁定は対象にしないため、固定単価で複数の同費用運用が生じ得ることを踏まえ、手法間の時系列完全一致ではなく費用と制約を中心に比較する。

対象期間がN区間、時間幅がdt時間の場合、年間基本料金単価28,861.92円/kWを `N*dt/8760` で按分する。契約電力相当値は対象期間内の最大買電電力とする。この値は基本料金の計算用であり、買電電力へ外から与える上限制約ではない。

DPのSOC格子は、初期・終端の50%を正確に含む等間隔の入れ子格子とする。最初の候補は19、37、73、145点である。各実験では格子点数、実際の間隔、状態遷移数を記録する。

## 5. 比較する手法

### 5.1 数理計画法

現行の `src/optimize_LP.py` は、同時充放電を禁止する二値変数を含むため、実際には混合整数線形計画法（MILP）である。連続SOCを用いるMILPを、DPの離散化誤差を測る基準候補とする。

一方、価格や効率の条件によっては、二値変数を外した線形計画法（LP）でも同じ最適値が得られる可能性がある。予備実験でLPとMILPの目的値、運用、計算時間を確認し、論文で「数理計画法」をどのモデルで代表させるか決める。

### 5.2 動的計画法

現行の `src/optimize_DP.py` は、SOCを状態として格子化し、時刻ごとに電力量料金だけを更新する。新しいDPでは、SOCごとに累積最大買電と累積電力量料金の非劣ラベルを保持し、終端で基本料金を含む電力料金を評価する。DPでは、SOC格子による近似の大きさと、格子数・保持ラベル数の増加による計算負荷を測る。

最初は現在の一様格子を使う。基本比較の結果から必要性が確認できた場合に、状態の丸め方や格子の配置を改善する。

## 6. 公平な比較の条件

比較結果にモデル差が混ざらないよう、次を揃える。

1. 同じ需要、PV、価格、対象期間を使う。
2. 同じSOC更新式、効率、電力上限、初期・終端条件を使う。
3. PV抑制、売電、同時充放電の扱いを揃える。
4. 共通の事後評価処理で、最大買電、基本料金、電力量料金、合計電力料金と全制約を再計算する。
5. 入力読込み、モデル構築、初回コンパイル、求解、結果保存の時間を区別する。
6. 計算環境、ソルバー版、スレッド数、時間制限を記録する。

最適解が複数存在する場合があるため、充放電時系列の完全一致を合格条件にはしない。費用と制約の一致を中心に確認する。

## 7. 正しさの検証

1. 数ステップの人工データを作り、手計算または全列挙で最適解を確認する。
2. SOCを同じ格子に制限した小規模な数理計画モデルとDPを比較する。
3. 同一の離散問題について、目的値が数値許容誤差内で一致することを確認する。
4. 電力収支、SOC遷移、SOC範囲、充放電上限、同時充放電、初期・終端SOC、最大買電と基本料金を検査する。
5. 数理計画法では終了状態、最良境界、最適性ギャップを保存する。

現在の仕様では、蓄電池を全時刻で待機させる経路が存在する。実行可能解が見つからない場合は、手法の性質と解釈する前に、格子生成、初期・終端状態、実装を確認する。

## 10. 先行研究の使い方

先行研究は次の目的に限定して利用する。

- 定式化や評価指標の見落としを確認する。
- 自分たちの結果と一致する点、異なる点を解釈する。
- 論文の関連研究節で、本研究の位置づけを説明する。
- 既に十分検証されている内容だけを主張することを避ける。

文献調査そのものを研究の中心にはしない。実験の進行を止めない範囲で、近い論文を優先して読む。現時点で確認済みの主要文献は次のとおり。

### T01：共通モデルを1枚の対応表にする

- 読む：本書4〜7節、`../src/optimize_LP.py`、`../src/optimize_DP.py`、`../config.json`。
- 作る：`notes/MODEL_SPEC.md`。変数名、意味、単位、電池内部/外部、時刻添字、両実装の表現、論文用の式を並べる。
- 固定する：SOCは区間境界にN+1点、電力・価格は区間ごとにN点。価格は円/kWh、電力はkW、時間幅はh、SOCの実体は蓄電量kWhとする。
- 電池内部側の充電・放電をc、dとすると、状態遷移は `e[t+1] = e[t] + dt*(c[t]-d[t])`、電力収支は `buy[t]+pv_used[t]+eta_d*d[t] = load[t]+c[t]/eta_c` とする。
- 共通モデルの電力料金は、対象期間最大買電に基づく按分基本料金と電力量料金の合計とする。最大買電は費用評価用であり、外生的な買電上限にはしない。
- 完了条件：目的関数・全制約・初期/終端条件が記載され、過去実装との差を説明できる。未解決の仕様は項目名付きで記録する。

- 作る：`notes/DATA_AND_ENVIRONMENT.md`。利用可能なPython、主要ライブラリとソルバーの版、データ列、単位、期間、件数、欠測、重複、価格の最小/最大値を記録する。既存環境が使えるかを先に確認する。

- 30分コード1〜48であることを確認できた場合、コード1が00:00、2が00:30、48が23:30となることを検査する。既存処理の結果を無検査で使わない。

### T04：人工データと独立した評価処理を作る

- 作る：`tests/small_cases/` の小規模ケースと `src/evaluate_solution.py`。
- ケースA：PVなし、効率1、価格・需要一定、初期＝終端。待機解について、電力量料金が価格×需要電力量、基本料金がテスト用係数×最大買電、合計が両者の和に一致する。
- ケースB：2時刻、効率1、PVなし、需要各1 kW、単価10/30円、時間幅1 h、容量2 kWh、初期＝終端1 kWh、SOC範囲0〜2 kWh、内部充放電上限1 kW、テスト用基本料金係数5円/kW。買電2/0 kWにより電力量料金20円、基本料金10円、合計30円となり、待機解45円より小さい。
- ケースC：一定価格で余剰PVがある例。PVを全量抑制する待機解と、PVを蓄えて後で使う解を手計算し、電力収支と損失を確認する。
- ケースD：正しい解のSOC、電力、終端値、最大買電または料金内訳を意図的に崩した入力を検査処理へ渡し、違反を検出できることを確認する。
- 上記は検証用設定であり、実データ用の設備条件とは別設定にする。
- 初期許容差：電力収支1e-6 kW、SOC収支/境界1e-6 kWh、費用差 `max(0.01円, 基準費用の絶対値×1e-8)`。適用した値を保存する。
- 完了条件：計算器から独立した処理で費用と全制約を再計算し、正しい例を通し、不正な例を検出できる。

### T05：数理計画側を実装する

- 作る：`src/solve_math_program.py`。同じモデルをLP/MILPの切替で解けるようにする。
- MILPでは実際の電力上限を使って充放電排他を表す。結果はT03の共通形式で返す。
- 全てのT04ケースを実行する。LPは目的値と同時充放電の有無を記録する。目的値の一致だけでLPの物理的妥当性を断定しない。
- 完了条件：手計算と合い、検査処理に合格する。最大買電、料金内訳、終了状態、最良境界、最適性ギャップを出力できる。

### T06：DP側を実装する

- 格子点数を設定から読み、初期・終端状態を厳密に含むことを検査する。格子間の遷移から内部充放電電力を求め、電力上限と需要への放電可能量を検査する。
- SOCごとに累積最大買電と累積電力量料金の非劣ラベルを保持し、支配されるラベルだけを除く。終端で基本料金を加えて合計電力料金を選び、最大買電を別の恣意的な格子へ丸めない。
- T04の全ケースを実行し、T03の形式で時系列と費用を出力する。
- 完了条件：手計算と合い、検査処理に合格する。最大買電と料金内訳、保持ラベル数、初回コンパイル時間と準備後の求解時間を記録できる。
